# 旅行攻略规划工作流

## 可用工具

| 工具 | 用途 | 注意 |
|---|---|---|
| `xhs_login_status` | 检查小红书服务/登录 | 排查问题时先调它 |
| `xhs_search` | 搜小红书笔记 | 浏览器自动化，**1~3分钟/次，严禁并行**，一次只搜一个关键词 |
| `xhs_note_detail` | 读笔记正文+评论 | 同上，慢；评论是避坑金矿 |
| `xhs_user_profile` | 挖优质博主系列内容 | 可选 |
| `dp_search` | 大众点评商户/分店搜索 | 每秒限1次；风控时降级 |
| `dp_shop` / `dp_reviews` | 点评商户详情/评价 | 常仅返回链接（风控），评分/人均改用 amap |
| `amap_poi_search` | POI 校验、坐标、评分、营业时间、**餐厅评分/人均** | 快 |
| `amap_geocode` | 地址→坐标（酒店/民宿） | 快 |
| `amap_route` | 点间距离/耗时（步行/公交/驾车） | 快 |

小红书不可用时（服务未启动），向用户说明启动方式后，退化为仅用高德 + 自身知识，并在产出中声明数据局限。大众点评同理（cn-scraper-mcp）。

## 阶段 1：需求澄清（一次问清，别挤牙膏）

目的地、日期与天数、同行人（老人/小孩/体力）、偏好（人文/自然/美食/亲子/摄影）、预算档位、住宿是否已订（已订则地址要用 amap_geocode 定位）、硬约束（如某天必须去某地）、忌口与禁忌。

## 阶段 2：小红书情报采集（串行！）

1. 关键词组合（3~6 个，逐个搜）：
   - `{目的地} {天数}天 攻略` — 主攻略（filters.sort_by=最多点赞）
   - `{目的地} 避坑` / `{目的地} 踩雷` — 负面情报（重点！）
   - `{目的地} 美食 本地人` — 吃的
   - `{目的地} 小众` / `{目的地} 路线` — 深度补充
   - 若临近出行：`{目的地} 攻略` 用 sort_by=最新 看时效
2. 从搜索结果挑 **3~6 篇**读详情：优先收藏数高、收藏/赞比高（干货型）、近期发布；避坑类必读评论区（load_all_comments=true, limit=20）
3. 边读边提取到结构化清单：
   - **POI 候选**：景点/餐厅/住宿区域（记博主原话名称）
   - **避坑**：哪个点别去/何时去/怎么买票便宜
   - **价格与时长**：门票、缆车、演出
   - **交通情报**：机场↔市区、跨城方式、市内堵点
4. **餐饮数据三角验证**（输出美食清单时）：`dp_search` 找分店（选离当日动线最近的）→ `amap_poi_search` 拿评分/人均/地址/电话 → 小红书口碑交叉确认；冲突时如实标注

## 阶段 3：高德校验与路线编排

1. 每个 POI 用 `amap_poi_search` 标准化：确认存在、拿坐标、营业时间、评分；同名多个时选与游记描述匹配的
2. 酒店/民宿用 `amap_geocode` 定位
3. 日程按**地理聚类**排（同片区一天）；用 `amap_route` 串联每天动线：
   - 相邻点步行 >30min → 改公交/打车评估
   - 每天含餐位与缓冲时间；早出晚归强度要匹配同行人体力
4. 关键交通节点：机场/车站↔酒店耗时、跨城班次类型（高铁/大巴）

## 阶段 4：输出 HTML 攻略

文件名：`{目的地}{天数}天攻略.html`（保存在当前目录）。设计风格参考 `examples/kunming-7days-itinerary.html`：浅色卡片、圆角、内嵌 CSS、`pit-*`/`trip-*` class 命名、移动端友好。

必备板块：
0. **美食清单**（逐日餐位：店名/分店选择理由/评分/人均/地址电话/三人预估）
1. **行程总览表**：日期 × 上午/下午/晚上 × 主题 × 交通
2. **逐日详细**：时间轴（时间-地点-交通方式与耗时-门票-贴士），每个地点标注来源博主
3. **美食清单**：店名-必点-人均-位置-来源
4. **住宿建议**：区域选择逻辑（结合交通动线）
5. **避坑汇总**：❗醒目呈现，注明来源
6. **数据来源**：小红书博主 @昵称（赞/藏数）+ 高德地图校验

原则：
- 每条建议**可溯源**：哪个博主说的 / 高德哪个数据
- 冲突信息（如某景点褒贬不一）要如实呈现两方并给结论
- 不确定的信息（价格变动、临时关闭）标注"出发前请核实"
